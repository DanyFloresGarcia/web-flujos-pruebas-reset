Etapa 1 · Preparación

Asegura que el entorno de datos e infraestructura cumpla con los prerrequisitos exactos antes de iniciar el flujo.

Accesos y permisos

Este flujo no parte de cero: reutiliza los accesos AWS ya otorgados en el flujo de Migración Configuración→Ejecución. Lo nuevo está del lado de GCP.

  • Nuevo (GCP): permisos IAM en el proyecto de GCP para Cloud Scheduler, Cloud Run (los dos servicios: ingesta y envío de audiencia), ejecución de Stored Procedures en BigQuery, y Secret Manager de GCP.
  • Nuevo: conexión VPN entre GCP y AWS, para que el Cloud Run de ingesta pueda acceder a bd_promocion_configuracion.
  • Ya cubierto (AWS): EventBridge, Lambda, SQS y Fargate ya están otorgados por el flujo anterior — validar únicamente que incluyan los recursos específicos de este flujo (si aplica un Fargate task nuevo).

Pendiente confirmar con Arquitectura/Plataforma quién otorga los accesos de GCP — el flujo anterior solo cubrió infraestructura AWS.

Checklist de preparación

  • Infraestructura: validar que los componentes involucrados tanto en GCP como en AWS (EventBridge, Lambda, SQS, Fargate) estén desplegados, operativos y con los permisos de red/IAM necesarios para interactuar entre sí.
  • Generación de datos: ejecutar el procedimiento almacenado [sch_cfg_audiencia].[usp_audiencia_promocion_segmento_invitado_generar].
  • Validación de origen: confirmar que la ejecución del SP haya poblado correctamente la tabla [sch_cfg_audiencia].[dts_audiencia_promocion_segmento].

Etapa 2 · Ejecución

Valida el paso a paso del orquestador en GCP (workflow-col-promocion-audiencias-procesar-ingesta) y su interacción con la infraestructura de AWS.

1

Disparo (Trigger)

Cloud Scheduler

Confirmar que el Cloud Scheduler (cschedule-col-promocion-audiencias-trigger-ingesta) detone el inicio del flujo a las 10:00 PM (o mediante ejecución manual).

2

Paso 1 · Ingesta

Cloud Run

Validar que Workflows invoque el primer servicio de Cloud Run (fn-accty-ingesta-rBc4-mysql). Este debe recuperar sus credenciales desde Secret Manager, conectarse vía VPN a la bd_promocion_configuracion en AWS, extraer los datos y almacenarlos en la capa raw.

3

Paso 2 · Procesamiento

BigQuery SP

Validar que Workflows inicie la ejecución del Stored Procedure sp_promocion_audiencia_col para procesar y cruzar la información extraída.

4

Paso 3 · Envío de audiencia

Cloud Run

Validar que Workflows invoque el segundo servicio de Cloud Run (fn-col-promocion-audiencias-enviar-audiencia) para que extraiga los datos procesados y realice la carga final hacia la bd_promocion_audiencia en AWS.

Etapa 3 · Validación

Se revisan los resultados de la migración directamente consultando el motor de base de datos de destino en AWS (bd_promocion_audiencia).

Casos de prueba

CP_F1_POS_01 · Carga exitosa

Happy path
Acción / Query
Consultar la tabla [sch_cfg_migracion].[trx_audiencia] en la BD Audiencia.
Resultado esperado
Los registros correspondientes a la promoción procesada se hayan insertado correctamente al finalizar el flujo.

CP_F1_POS_02 · Integridad de datos

Happy path
Acción / Query
Comparar una muestra de registros en [sch_cfg_migracion].[trx_audiencia] (BD Audiencia) contra los datos que se originaron.
Resultado esperado
La información de los segmentos, invitados y promociones no presenta truncamientos, valores nulos inesperados o pérdida de caracteres especiales.

CP_NEG_01 · Fallo de inserción / rollback

Negativo
Acción / Query
Forzar un error en medio de la carga final (desconexión con la BD).
Resultado esperado
En la BD Audiencia no existen registros parciales, huérfanos o corruptos en [sch_cfg_migracion].[trx_audiencia], asegurando la atomicidad de la carga.
