Etapa 1 · Preparación

Condiciones que deben estar dadas en bd_promocion_ejecucion y en el entorno de origen antes de registrar un invitado nuevo.

Accesos y permisos

Este flujo reutiliza la mayoría de servicios AWS ya otorgados, pero introduce componentes nuevos.

  • Ya cubierto: API Gateway, Lambda, SNS, SQS y CloudWatch ya están otorgados por el flujo de Migración Configuración→Ejecución.
  • Nuevo: Amazon DynamoDB (tabla col-audiencia_invitados_nuevos) — no estaba contemplada en los accesos anteriores, hay que solicitarla aparte.
  • Nuevo: integración saliente hacia el Webhook de Google Chat (para las alertas de error) — validar si requiere whitelist de red saliente o alguna credencial adicional.
  • Nuevo: acceso a la cola de mensajes muertos (sqs-col-audiencia-invitados_nuevos_dlq) para revisar fallos de inserción.

Checklist de preparación

  • Estado base de datos: validar que las etapas previas ya estén migradas en bd_promocion_ejecucion.
  • Regla de negocio (Admisión): confirmar en la base de datos de ejecución que la etapa de admisión se encuentre en estado activa y con la fecha apta, permitiendo el ingreso de nuevos registros.
  • Generación de origen: preparar el entorno de la web del casino para la creación de un nuevo invitado, teniendo listos los datos (payload) que enviará el Webhook.

Etapa 2 · Ejecución

Flujo disparado por evento (no programado) desde el Webhook de Calimaco hasta la carga final en bd_promocion_ejecucion.

1

Ingesta y validación de header

Calimaco → API Gateway

Validar que el Amazon API Gateway se encuentre desplegado y operativo. Validar la creación del invitado y que el Webhook Calimaco envíe la petición al API Gateway incluyendo estrictamente el header X-Amz-Invocation-Type: Event. Validar que el API Gateway acepte la petición asíncrona retornando un código de estado HTTP 201.

2

Orquestación y envío

Lambda + DynamoDB

Validar que la función AWS Lambda "Orquestador Invitados Nuevos COL" y la tabla de Amazon DynamoDB (col-audiencia_invitados_nuevos) se encuentren desplegadas.

3

Mensajería

SNS / SQS

Confirmar que el tema de Amazon SNS y la cola de Amazon SQS correspondiente estén desplegados. Comprobar que el flujo publique el evento en SNS y este lo enrute correctamente hacia la SQS.

4

Consumo y carga final

Lambda

Validar que la función AWS Lambda "Asignación de Promociones" esté desplegada. Validar que esta función consuma el mensaje de SQS y ejecute el registro final del invitado en las tablas de bd_promocion_ejecucion (audiencia y participante).

Etapa 3 · Validación

Casos de prueba end-to-end y de manejo de errores en cada punto de falla del flujo.

Casos de prueba

CP01 · Registro completo E2E

Happy path
Acción / Query
Enviar el registro de un invitado válido desde la web del casino asegurando la presencia del header X-Amz-Invocation-Type: Event.
Resultado esperado
Confirmar la respuesta 201 del API Gateway. Validar la existencia del registro en DynamoDB y que las tablas trx_audiencia y trx_participante en bd_promocion_ejecucion contengan la información del invitado sin pérdida de datos.

CP01 · Fallo de invocación por header ausente/inválido

Negativo
Acción / Query
Enviar el payload desde el Webhook de Calimaco hacia el API Gateway omitiendo el header X-Amz-Invocation-Type: Event (o enviando un valor incorrecto como RequestResponse).
Resultado esperado
La petición es rechazada (no retorna 201) y no se inicia el flujo hacia la Lambda orquestadora ni se registra nada en DynamoDB.

CP02 · Flujo de error y alerta en Google Chat

Negativo
Acción / Query
Inyectar un payload malformado que supere la validación inicial pero haga fallar al AWS Lambda Orquestador.
Resultado esperado
El error detona el flujo hacia la SQS de errores, invocando al lambda-notificador, y la alerta llega exitosamente al Google Chat Webhook.

CP03 · Fallo de inserción en BD destino

Negativo
Acción / Query
Simular un error de credenciales entre la Lambda Suscriptor y la bd_promocion_ejecucion.
Resultado esperado
El participante no se registra, y el mensaje pasa a la cola de mensajes muertos (sqs-col-audiencia-invitados_nuevos_dlq) para evitar pérdida de datos.

CP04 · Etapa de admisión inactiva

Negativo
Acción / Query
Configurar la base de datos de ejecución para que la etapa de admisión esté inactiva. Detonar la creación de un invitado válido desde la web.
Resultado esperado
Aunque se registre en DynamoDB (si la lógica lo permite allí), el sistema final rechaza la inserción en las tablas de bd_promocion_ejecucion, respetando la regla de negocio.
