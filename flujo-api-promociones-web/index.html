Definition of Ready (DoR)

Accesos y permisos

Este flujo introduce accesos que no estaban en los flujos anteriores. Se diferencian por ambiente/cuenta: DEV en la cuenta Developer de Virginia, QA en la cuenta Developer de Ohio.

Ambiente DEV · Virginia (cuenta Developer)
  • API-key: las api-key de las APIs de Home y Web de este ambiente, para el front de pruebas del casino.
Ambiente QA · Ohio (cuenta Developer)
  • API-key: las api-key de las APIs de Home y Web de este ambiente, para el front de pruebas del casino.

Pre requisitos técnicos

  • Ambiente de pruebas del front del casino enlazado a las APIs de Home y Web.
Configuración de datos de prueba
  • Configuración migrada: contar con la configuración de las promociones migrada a la BD_PROMOCION_EJECUCION.

Etapa 3 · Validación

Casos de prueba positivos y negativos sobre la carga de promociones.

Casos positivos

CP-01 · Carga exitosa de promociones

Happy path
Acción
Ingresar con un usuario con promociones asignadas.
Resultado esperado
El servicio devuelve HTTP 200 y el frontend renderiza el contenido de las promociones en el orden correcto.

CP-02 · Carga de contenido multimedia

Happy path
Acción
Revisar las imágenes y textos devueltos por el servicio.
Resultado esperado
Las imágenes y textos cargan correctamente, sin errores de formato.

Casos negativos

CN-01 · Usuario sin promociones

Negativo
Acción
Ingresar con un usuario que no califica.
Resultado esperado
El servicio devuelve una lista vacía y la interfaz muestra un mensaje de estado vacío.

CN-02 · Parámetros inválidos

Negativo
Acción
Enviar id_online o numero_documento erróneos o nulos.
Resultado esperado
El servicio responde error 400: la validación exige que la petición incluya el id del jugador online (id_online).

CN-03 · Promoción sin contenido

Negativo
Precondición
Activar una promoción en la BD de ejecución sin ruta en la BD de contenido.
Resultado esperado
